01 · Database / SQL

อ่าน ~35 นาที · ทวนการ์ด D+1 · self-check D+7 · อ้างอิงหลัก: PostgreSQL Docs (postgresql.org/docs), Use The Index Luke (use-the-index-luke.com)

1. ต้องเข้าใจ

Relational model & keys

  • ตาราง = relation, แถว = row/tuple, คอลัมน์ = column/attribute
  • Primary key — ระบุแถวไม่ซ้ำ, ห้าม NULL · Foreign key — อ้างถึง PK ของอีกตาราง (บังคับ referential integrity) · UNIQUE — ห้ามซ้ำแต่รับ NULL ได้ · CHECK / NOT NULL — constraint ระดับคอลัมน์
  • NULL = “ไม่ทราบค่า” ไม่ใช่ 0 หรือ “” — เปรียบเทียบด้วย IS NULL ไม่ใช่ = NULL; NULL = NULL ไม่เป็น true (three-valued logic: TRUE/FALSE/UNKNOWN) — กับดักเวลา NOT IN (subquery ที่มี NULL) จะได้ผลว่าง

Normalization

  • 1NF — ทุกช่องเก็บค่าเดี่ยว (atomic) ไม่มี list ในช่อง
  • 2NF — 1NF + ไม่มี partial dependency (คอลัมน์ไม่ขึ้นกับ “บางส่วน” ของ composite key)
  • 3NF — 2NF + ไม่มี transitive dependency (non-key ขึ้นกับ non-key อีกที)
  • BCNF — ทุก determinant ต้องเป็น candidate key (เข้มกว่า 3NF)
  • หลักคิด: normalize เพื่อลด redundancy/update anomaly; denormalize ได้เมื่ออ่านหนัก (ยอม redundancy แลกความเร็ว) — ต้องบอก trade-off ได้

Transactions & ACID

  • Atomicity — สำเร็จทั้งหมดหรือไม่มีเลย · Consistency — จาก valid state ไป valid state (constraint ยังถูก) · Isolation — transaction concurrent ไม่รบกวนกัน · Durability — commit แล้วข้อมูลอยู่จริงแม้ไฟดับ
  • COMMIT / ROLLBACK / SAVEPOINT; ตัวอย่างBank: หักบัญชี + เพิ่มบัญชี ต้องอยู่ใน transaction เดียว

Concurrency anomalies & isolation levels

  • Dirty read — อ่านค่าที่คนอื่นยังไม่ commit · Non-repeatable read — อ่านเดิม 2 ครั้งได้ค่าไม่เท่า (มีคน UPDATE commit ระหว่างนั้น) · Phantom read — query เดิม 2 ครั้งได้ “จำนวนแถว” ไม่เท่า (มีคน INSERT ระหว่างนั้น)
  • Lost update — สอง transaction อ่านค่าเดียวกันแล้วเขียนทับกัน (เกิดได้แม้ RC — ต้องใช้ lock SELECT FOR UPDATE หรือ optimistic version)

Indexes

  • ส่วนใหญ่คือ B-tree — เร่ง equality + range + ORDER BY; hash index ใช้ได้แค่ equality
  • Composite index (a,b,c) ใช้ได้ตาม leftmost prefix: query ที่กรอง a / a,b / a,b,c ใช้ได้ — กรอง b อย่างเดียวไม่ใช้ (กับดักข้อสอบยอดฮิต)
  • Index ทำให้ อ่านเร็ว เขียนช้าลง (ทุก INSERT/UPDATE ต้องอัปเดต index) + กินพื้นที่ — อย่าใส่พร่ำเพรื่อ
  • EXPLAIN ANALYZE — ดู plan จริง: seq scan vs index scan, rows estimate; ใช้ตอบคำถาม “ทำไมช้า”
  • กับดักทำให้ index ใช้ไม่ได้: ใส่ฟังก์ชันบนคอลัมน์ (WHERE lower(email)=…), implicit cast ชนิดไม่ตรง, LIKE '%x%'

Query ที่ต้องแม่น

  • Join: INNER = ตรงกันทั้งคู่ · LEFT = เอาทั้งซ้าย+คู่ที่ตรง (ไม่ตรง = NULL ทางขวา) · RIGHT = กลับกัน · FULL = ทั้งสองฝั่ง · CROSS = คูณกันทุกแถว
  • Logical execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT — จึงอธิบายได้ว่า ทำไม WHERE กรอง aggregate ไม่ได้ ต้องใช้ HAVING
  • Aggregate: COUNT/SUM/AVG/MIN/MAX + GROUP BY; COUNT(*) นับทุกแถว, COUNT(col) ไม่นับ NULL
  • Window functions — คำนวณข้ามแถวแต่ไม่ยุบแถว: ROW_NUMBER() เรียงไม่ซ้ำ · RANK() เสมอแต่ข้ามเบอร์ (1,1,3) · DENSE_RANK() ไม่ข้าม (1,1,2) · LAG/LEAD เทียบแถวก่อน/หลัง · ใช้ PARTITION BY แบ่งกลุ่ม
  • Delete ซ้ำ: หา row_number() > 1 ใน partition แล้วลบ — โจทย์ classic
  • Pagination: OFFSET มากๆ ช้า (ต้องกวาดทิ้ง) — ทางที่ดีคือ keyset pagination (WHERE id > :last ORDER BY id LIMIT n)

N+1 & application-level

  • N+1 query — ดึง list 1 ครั้ง แล้ว loop ยิงรายแถวอีก N ครั้ง → แก้ด้วย JOIN / eager loading / batch WHERE id IN (…)
  • SQL Injection — เกิดจากต่อสตริง SQL กับ input → แก้ที่ parameterized query / prepared statement เท่านั้น (escape/StringReplace ไม่นับว่าแก้) — ดูหัวข้อ 03
  • NoSQL types: document (MongoDB), key-value (Redis), wide-column (Cassandra), graph (Neo4j) — เลือกตาม access pattern + scale; ไม่ได้มาแทน SQL ทั้งหมด

โน้ต: PostgreSQL default = Read Committed และ Repeatable Read ของ PG กัน phantom ได้จริง (snapshot isolation — เข้มกว่ามาตรฐาน SQL); MySQL InnoDB default = Repeatable Read และกัน phantom ด้วย next-key lock (locking reads) — ข้อสอบชอบถาม default มาก

  • ACID — Atomicity, Consistency, Isolation, Durability (เรียงนี้)
  • SELECT order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
  • RANK vs DENSE_RANK vs ROW_NUMBER — ข้ามเบอร์ / ไม่ข้าม / ไม่ซ้ำเสมอ
  • Leftmost prefix rule ของ composite index
  • Normalization: 1NF atomic, 2NF no partial, 3NF no transitive, BCNF every determinant is candidate key
  • Update lost แม้ RC ก็เกิด → SELECT … FOR UPDATE / version column

3. กับดักข้อสอบ

  • WHERE กับ aggregate (เช่น WHERE COUNT(*)>5) — ผิด ต้องใช้ HAVING
  • COUNT(*) vs COUNT(col) ต่างกันเมื่อมี NULL — ข้อสอบตัวเลขชอบหลอกตรงนี้
  • LEFT JOIN แล้วใส่เงื่อนไขของตารางขวาใน WHERE → กลายเป็น INNER JOIN โดยไม่ตั้งใจ (ต้องย้ายเงื่อนไขไป ON)
  • Index (a,b) กับ query WHERE b=… — ตอบว่าไม่ใช้ leftmost
  • TRUNCATE = ไม่ log รายแถว / reset identity ได้ / เร็วกว่า DELETE; DELETE มี WHERE ได้, TRUNCATE ลบทั้งตาราง (DDL)
  • DDL (CREATE/ALTER/DROP) vs DML (SELECT/INSERT/UPDATE/DELETE) vs DCL (GRANT/REVOKE) — ถ้าถามหมวด ให้ตอบเป๊ะ

4. Self-check (ปิดหน้า ตอบก่อน)

Q1: ACID ย่อจากอะไร อธิบายแต่ละตัวสั้นๆA: Atomicity (ทั้งหมดหรือไม่เลย), Consistency (constraint/valid state ยังถูก), Isolation (concurrent ไม่รบกวนกัน), Durability (commit แล้วอยู่จริง)
Q2: Non-repeatable read กับ phantom read ต่างกันยังไงA: Non-repeatable = อ่าน “แถวเดิม” ได้ค่าเปลี่ยน (UPDATE commit กลางทาง); phantom = ได้ “ชุดแถว” เปลี่ยน (INSERT/DELETE commit กลางทาง)
Q3: ทำไม composite index (a,b,c) ไม่ช่วย query WHERE b=1A: B-tree เรียงตาม a ก่อน — เข้าไม่ถึง b ได้ถ้าไม่รู้ a (leftmost prefix rule)
Q4: ลำดับ logical execution ของ SELECT มีอะไรบ้างA: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
Q5: ROW_NUMBER กับ RANK ให้ผลต่างกันยังไงเวลาเสมอกันA: ROW_NUMBER ให้ 1,2,3 เสมอไม่ว่าเสมอ; RANK ให้ 1,1,3 (ข้าม); DENSE_RANK ให้ 1,1,2
Q6: N+1 query คืออะไร แก้ยังไงA: 1 query ดึง list + N query ต่อแถว — แก้ด้วย JOIN / eager load / WHERE IN (batch)
Q7: Lost update ต่างจาก dirty read ยังไง และกันด้วยอะไรA: Lost update = สองคนอ่านค่าเดียวกันแล้วเขียนทับกัน (ค่าที่ commit ถูกต้อง ไม่ได้อ่านของ dirty); กันด้วย lock (FOR UPDATE) หรือ optimistic version check
ท่อง 3 อย่างวันนี้: ACID · ตาราง isolation level 4 ระดับ · SELECT execution order (FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT)
