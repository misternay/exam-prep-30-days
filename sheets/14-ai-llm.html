14 · AI Fundamental: LLM

อ่าน ~40 นาที · อ้างอิงหลัก: Attention Is All You Need (Vaswani et al.), Anthropic/OpenAI model docs, InstructGPT paper (RLHF)

1. ต้องเข้าใจ

LLM ทำงานยังไง (ระดับที่ต้องตอบได้)

  • LLM = โมเดลทางสถิติที่ทำนาย token ถัดไป จากลำดับที่ผ่านมา (next-token prediction) แล้วอลุ่มตามความน่าจะเป็น (sampling)
  • สถาปัตยกรรมคือ Transformer; หัวใจคือกลไก attention — แต่ละ token มอง token อื่นในบริบททั้งหมดเพื่อถ่วงน้ำหนักความสำคัญ (จึงเข้าใจบริบทได้ดีกว่าโมเดลแบบเก่า)
  • สิ่งที่ต้องประกาศให้ชัดตอนตอบข้อสอบ: โมเดลไม่ “รู้ข้อเท็จจริง” — มันเลียนแบบรูปแบบของข้อความที่เคยเห็น จึงเกิด hallucination ได้เสมอ; การ “ยืนยันข้อเท็จจริง” ต้องมาจากภายนอก (RAG/tool/คนตรวจ)
  • ขนาด = parameters (น้ำหนักในเครือข่าย; หลายพันล้านถึงหลายล้านล้าน) — โมเดลเป็นไฟล์น้ำหนัก + โค้ดรัน (inference); ไม่ได้ lookup อินเทอร์เน็ตเอง

Token & context

  • Token = ชิ้นข้อความที่โมเดลอ่าน/เขียน (คำย่อย/หลายตัวอักษร/สัญลักษณ์) — ไทยมักกิน token ต่อตัวอักษรมากกว่าอังกฤษ
  • Tokenization — แปลงข้อความเป็น token ด้วยชุดที่ฝึกมา (BPE แนวคิด); ตัวเลข/โค้ดไม่ใช่ “หนึ่งหน่วยสมบูรณ์” — ส่วนหนึ่งของปัญหาคำนวณผิด
  • Context window — จำนวน token สูงสุดที่โมเดลเห็นต่อการเรียกหนึ่งครั้ง (input + output รวม; ยิ่งยาว = แพง + ช้า + คุณภาพกลางๆ ลด)
  • ราคาคิดตาม input/output token — เข้าใจทำไม context engineering ถึงมีค่า (เชื่อมหัวข้อ 04)

3 ขั้นตอนการฝึก (ต้องท่อง)

  1. Pre-training — เทรนกับข้อความมหาศาล (ทำนาย token ถัดไป) → ได้โมเดลที่ “เข้าใจภาษาและโลก” แต่ยังเป็นแบบ “ต่อข้อความ” ไม่ได้ตั้งใจทำตามคำสั่ง
  2. Supervised Fine-tuning (SFT / instruction tuning) — เทรนต่อกับตัวอย่าง “คำสั่ง → คำตอบ” เพื่อให้ทำตามคำสั่งได้เป็น
  3. RLHF / alignment (Preference tuning) — ให้คนจัดอันดับ/ให้รางวัลคำตอบ → ปรับให้ตอบที่มีประโยชน์และปลอดภัยตามที่มนุษยชาติพึงพอใจ

ระดับรู้จักเพิ่ม: DPO คือทางเลือกแทน RLHF ที่นิยมในยุคหลัง; “post-training” = ชั้น 2+3 รวมกัน

พารามิเตอร์ตอน infer (ใช้บ่อย)

  • Temperature — สูง = สุ่ม/สร้างสรรค์, ต่ำ → 0 = ใกล้ deterministic → งานข้อเท็จจริง/โค้ด/สกัดข้อมูลใช้ต่ำลง
  • Top-p (nucleus) / Top-k — จำกัด pool ที่จะสุ่มจาก — คำถามมักถามว่า “ทั้งสองคุมความหลากหลายต่างกันแค่” (temperature เปลี่ยนหน้าความน่าจะเป็น; top-p ตัดหาง)
  • Max output tokens — เพดานความยาวคำตอบ; stop sequences — เงื่อนไขหยุด

Embeddings — สะพานสู่ RAG

  • Embedding = แปลงข้อความเป็น vector ที่ “ความหมายใกล้ = ระยะใกล้” ใช้ค้น (semantic search), จัดกลุ่ม, แนะนำ, RAG
  • คนละตัวกับโมเดลแชต (embedding model เล็กกว่า ถูกกว่า เร็ว) — จำไว้ว่า RAG ใช้ทั้ง embedding model (ค้น) และ LLM (อ่าน/ตอบ)

Hallucination & การควบคุม

  • สาเหตุ: โมเดลทำนายต่อจากรูปแบบ ไม่มีฐานข้อเท็จจริง — confidence ไม่ผูกกับความถูกต้อง; งานในความจำ (วันที่สด, ข้อมูลเฉพาะองค์กร) = เสี่ยงสูง
  • ลดความเสี่ยง: ให้ context ที่ถูกต้อง (RAG), ให้อ้างอิง/quote จากเอกสาร, บังคับ format (JSON ที่ตรวจได้), verifier/ตรวจซ้ำ, ใช้ tool ดึงข้อมูลสด, ตั้ง temp ต่ำ — แต่ไม่มีวิธีไหนการันตี 100%

ปรับโมเดลแบบอื่นๆ

  • Fine-tuning — เทรนต่อจากน้ำหนักเดิม (SFT/LoRA) เพื่อสอนงาน/สไตล์; ควรมีข้อมูลสะอาด + มี eval; อย่าใช้แก้ “ทั้งเรื่องความรู้” (จะล้าสมัย + อาจลดความสามารถเดิม)
  • Quantization — ย่อความละเอียดของน้ำหนัก (เช่น 4-bit) → กินหน่วยความจำ/ราคาน้อยลง เร็วขึ้น แลกความแม่นเล็กน้อย (โจทย์ชอบถามคำตอบนี้)
  • Distillation — ให้โมเดลใหญ่เป็นครู สร้างข้อมูลสอนโมเดลเล็ก
  • Prompting vs RAG vs fine-tune — ลำดับ: prompt → RAG → fine-tune (รายละเอียดตารางในหัวข้อ 04)

Evaluation

  • Benchmark สาธารณะ (เช่น MMLU, GSM8K, HumanEval แนวคิด) — ใช้เทียบโมเดลระดับตลาด; มีข้อจำกัด: อาจถูกเทรนมาเพื่อ benchmark (contamination) หรือไม่ตรงงานเรา
  • Eval ของเราเอง — ชุดงานจริง + เกณฑ์ผ่านชัด (ชอบตรวจด้วยคนหรือ verifier อีกชั้น) — ที่ใช้ตัดสินใจจริงในองค์กร
  • ประเมินงาน generative ใช้ người chấm/criteria; งานสกัดข้อมูลใช้ exact/fuzzy match

ราคา & การเลือกโมเดล

  • โมเดลใหญ่ = ฉลาดกว่าโดยเฉลี่ย แต่แพงกว่า+ช้ากว่า; โมเดลเล็ก = เร็ว/ถูก งานง่าย (classify, สกัดข้อมูล, จัดรูปแบบ) พอแล้ว — ตัดสินตามงาน + งบ + privacy (บนเครื่อง vs cloud)
  • Latency มีหลายส่วน: queue, prompt ประมวลผล (prefill ∝ size input), การ generate (decode ∝ size output)
  • Model family ตัวอย่าง: Claude (Opus/Sonnet/Haiku = ใหญ่/กลาง/เล็ก), GPT, Gemini, Llama (open weights), โมเดลจีน/โซน — รู้แนว “หลายเกรดเลือกตามงาน”

2. ต้องจำ

  • LLM = next-token predictor บน Transformer + attention; ไม่มีฐานข้อเท็จจริงในตัวเอง
  • 3 ขั้นฝึก: Pretrain → SFT → RLHF/alignment
  • Temperature (สุ่ม) / Top-p (ตัดหางความน่าจะเป็น) / max tokens; งาน fact ใช้ temp ต่ำ
  • Context window นับ input+output เป็น token; ราคาต่อ token
  • Embedding = vector ความหมาย → RAG
  • Quantization = ย่อความละเอียดน้ำหนัก; Fine-tune = สอนพฤติกรรม; RAG = ให้ความรู้
  • Hallucination เกิดจากหลักการทำงาน ไม่ใช่ bug — ลดด้วย context/tool/verify เต็มที่ก็ไม่ 100%
  • Benchmark เทียบตลาด; eval ของเราตัดสินจริง

3. กับดักข้อสอบ

  • “โมเดลค้นเว็บเองได้/จำการสนทนาได้เอง” — ผิด; ทุกอย่างมาจากสิ่งที่ระบบป้อนให้ (context/tool) หรือน้ำหนักที่ฝึกมา
  • Temperature = 0 แล้วได้ผลเหมือนเดิม 100% — ไม่เป๊ะระดับฮาร์ดแวร์/ผู้ให้บริการ แต่แนวคิดคือ deterministic ที่สุด
  • Fine-tune ไว้ “อัปเดตความรู้ล่าสุด” — ผิดแนว; ใช้ RAG; fine-tune เหมาะกับพฤติกรรม/รูปแบบ
  • “Context window ใหญ่ = ไม่ต้อง RAG” — ไม่จริงเสมอ: ราคา/คุณภาพกลางลำดับ/latency แย่ และยังต้องมีข้อมูลจะใส่ให้ถูกจังหวะ
  • RLHF = เทรนความรู้ใหม่ — ไม่ใช่; มันปรับ “การเลือกคำตอบตามที่คนชอบ/ปลอดภัย” หลัง SFT

4. Self-check (ปิดหน้า ตอบก่อน)

Q1: อธิบายการทำงานของ LLM หนึ่งย่อหน้าแบบที่เข้าใจจริงA: โมเดลทำนาย token ถัดไปจากบริบท (สถาปัตยกรรม Transformer + attention ถ่วงน้ำหนักความสำคัญของทุก token) ฝึกจากข้อความมหาศาล → เก่งภาษาตามรูปแบบสถิติ แต่ไม่มีฐานข้อเท็จจริงในตัว จึงต้องคิดเรื่อง hallucination เสมอ
Q2: 3 ขั้นตอนการฝึกโมเดลเรียงตามลำดับA: 1) Pretraining ทำนาย token 2) SFT ทำตามคำสั่ง/ตัวอย่าง 3) RLHF/Preference alignment ให้ตอบที่มีประโยชน์-ปลอดภัยตามที่คนชอบ
Q3: Temperature กับ top-p ต่างกันยังไงA: temperature สเกลความ “คม/แบน” ของความน่าจะเป็นก่อนสุ่ม (สูง=หลากหลาย); top-p ตัดเฉพาะกลุ่มความน่าจะเป็นสะสมถึง p แล้วสุ่มในนั้น (ตัดหาง) — ใช้คุมความสุ่มคนละกลไก
Q4: ทำไม LLM hallucinate และลดได้ยังไงA: เพราะเลียนรูปแบบสถิติ ไม่มีแหล่งข้อเท็จจริง — ลดด้วยการป้อน context ที่ถูก (RAG), บังคับอ้างอิง, เทียบกับ tool, verifier, temp ต่ำ; ไม่มีทาง elimination 100%
Q5: Quantization คืออะไร แลกอะไรA: ลดความละเอียดของตัวเลขน้ำหนัก (เช่น fp16→4-bit) ให้โมเดลกิน RAM น้อยลง เร็วขึ้น/ถูกลง แลกกับคุณภาพที่อาจลดลงเล็กน้อย
Q6: Benchmark กับ eval ของเราเองต่างกันเมื่อไรใช้A: benchmark = สาธารณะ ใช้เทียบตลาด (อาจ contamination/ไม่ตรงงานเรา); eval ของเรา = ชุดงานจริง+เกณฑ์ของเรา ใช้ตัดสินใจ deploy จริง
Q7: เลือกโมเดลเล็กหรือใหญ่ ตัดสินจากอะไร 3 อย่างA: ความซับซ้อนงาน (reasoning ต้องใหญ่), งบ/ราคาต่อ token+latency, และข้อกำหนด privacy/ที่ตั้งข้อมูล (บนเครื่อง vs cloud)
ท่อง 3 อย่างวันนี้: 3 ขั้นฝึก (Pretrain→SFT→RLHF) · temperature=สุ่ม / top-p=ตัดหาง · RAG=ความรู้ / fine-tune=พฤติกรรม / quant=ย่อโมเดล
