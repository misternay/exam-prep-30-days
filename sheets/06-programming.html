เข้าใจต้องจำกับดักSelf-check

06 · Programming

อ่าน 2 รอบ (D1: ข้อมูล+อัลกอริทึม, D2: กระบวนทัศน์+concurrency) · อ้างอิงหลัก: Big-O Cheat Sheet, MDN, ภาษาเป้าหมายของข้อสอบ

1. ต้องเข้าใจ

โครงสร้างข้อมูล & ความซับซ้อน (round 1)

โครงสร้างเข้าถึงค้นหาเพิ่ม/ลบโน้ต
ArrayO(1)O(n) (sorted+binsearch O(log n))O(n) กลาง, O(1) ท้าย (amortized)ต่อเนื่องในหน่วยความจำ cache ดี
Linked listO(n)O(n)O(1) ถ้ารู้ตำแหน่งโหนดสุ่มไม่เร็ว แต่แทรก/ลบในที่ได้
Hash table—O(1) เฉลี่ย / O(n) แย่สุดO(1) เฉลี่ยชนกันเยอะ = เสื่อม; ไม่เรียงลำดับ

  • Big-O คิด worst-case เป็นหลัก; บอกได้ทั้งเวลาและพื้นที่ (space)
  • Stack = LIFO (undo, call stack), Queue = FIFO (BFS, งานคิว), Deque = สองทาง
  • Tree traversal: in/pre/post-order (DFS), level-order (BFS); BST = ซ้ายน้อย–ขวาใหญ่ → in-order ได้เรียง
  • Graph: BFS หา shortest path ในกราฟไม่ถ่วงน้ำหนัก (ใช้ queue); DFS สำรวจ/หา cycle (ใช้ stack/recursion)

อัลกอริทึมที่ต้องรู้ค่า

  • Sorting: merge sort O(n log n) ทุกกรณี + stable + ใช้ memory O(n); quick sort เฉลี่ย O(n log n) แย่สุด O(n²) (pivot ไม่ดี) + in-place; heap sort O(n log n) in-place ไม่ stable
  • Binary search O(log n) ใช้กับ “เรียงแล้ว” — จุดพลาด: เงื่อนไขขอบ (lo <= hi), mid overflow
  • Two pointers / sliding window — ลด O(n²)→O(n) สำหรับ substring/คู่ผลรวม; hashmap complement สำหรับ two-sum
  • จำสูตรต้นทุนพอ: ทุกคู่ O(n²), ทุกครึ่ง O(log n), เรียง+กวาด O(n log n)

กระบวนทัศน์ (round 2)

  • OOP 4 เสาหลัก: Encapsulation (ซ่อน state), Abstraction (เผยเฉพาะจำเป็น), Inheritance (is-a), Polymorphism (interface เดียวหลายรูปแบบ)
  • Overload vs Override: overload = เมธอดชื่อเดียวกัน พารามิเตอร์ต่าง (compile-time); override = คลาสลูกเขียนทับเมธอดแม่ (runtime)
  • FP: pure function (ผลขึ้นกับ input เท่านั้น ไม่มี side effect), immutability, higher-order function, map/filter/reduce; ข้อดี: test ง่าย, parallel ง่าย
  • เลือกเครื่องมือ: OOP จัดโครง state, FP จัดการ transform ข้อมูล — ใช้ผสมกันได้ (เป็นคำตอบที่ดีกว่าเลือกข้าง)

Concurrency

  • Process vs Thread: process แยกหน่วยความจำ (ปลอดภัยกว่า, คุยกันยาก/แพง), thread ใช้หน่วยความจำร่วม (เร็วในการสื่อสาร, แชร์ state → race condition)
  • Async/await — ไม่ได้แปลว่า parallel; มันคือการรอแบบไม่บล็อก (I/O-bound); งาน CPU-bound ต้องใช้ process/worker จริง
  • Race condition — ผลขึ้นกับจังหวะ; แก้ด้วย lock/mutex, atomic operation, immutable data, หรือ confine ให้ thread เดียวแตะ
  • Deadlock เกิดเมื่อ 4 เงื่อนไขครบ (Coffman): mutual exclusion, hold & wait, no preemption, circular wait — แก้ = ทำลายสักข้อ (เช่น lock ordering, timeout)
  • Mutex vs Semaphore: mutex = ล็อก 1 ที่ (เจ้าของชัดเจน); semaphore = นับจำนวน token ที่ผ่านได้ N ตัว

หน่วยความจำ & กับดักภาษา

  • Stack: ตัวแปร local/เรียกฟังก์ชัน เร็ว จำกัด ขนาด (ล้น = stack overflow) · Heap: object ทั้งหลาย โตได้ จัดการด้วย GC (หรือ manual)
  • Pass by value vs reference: primitive ส่งค่าคัดลอก; object ส่ง reference — ระวังฟังก์ชันแก้ object ที่ผู้เรียกถืออยู่ (มีผลข้างเคียง)
  • Floating point: 0.1 + 0.2 ≠ 0.3 (binary ไม่แทนทศนิยมได้เป๊ะ) — เรื่องเงินใช้ decimal/integer สตางค์; ห้ามเทียบ == กับ float
  • Integer overflow — ล้นขอบแล้ววนค่ากลับ (เช่น int32 เกิน ~2.1×10⁹); ภาษา modern บางตัว throw
  • String immutable (Java/C#/Python) — ต่อสตริงในลูปด้วยตัวเดิมได้ของใหม่ทุกครั้ง → ใช้ builder/list join
  • Null/undefined — null dereference คือ bug อันดับต้น; ใช้ optional/type system, ตรวจก่อนใช้

Clean code (ออกข้อสอบเชิงเขียน)

  • ชื่อสื่อนาม – ตัวแปร/ฟังก์ชันบอก “ทำอะไร” · ฟังก์ชันเล็กทำเรื่องเดียว · เลี่ยง nesting ลึก (early return/guard clause)
  • Comment อธิบาย why ไม่ใช่ what; code ที่ดีไม่ต้องมี comment อธิบายตัวมันเอง
  • Error handling: ไม่กลืน exception เงียบๆ; fail fast; error message บอก context

2. ต้องจำ

  • Big-O ของ: array access O(1), hash เฉลี่ย O(1), balanced BST O(log n), sorting เปรียบเทียบ O(n log n), binary search O(log n)
  • Stack LIFO / Queue FIFO; BFS=queue, DFS=stack
  • OOP 4 เสาหลัก; overload(compile) vs override(runtime)
  • Deadlock 4 เงื่อนไข (mutual exclusion, hold&wait, no preemption, circular wait)
  • 0.1+0.2≠0.3 → เงินใช้ decimal; float ห้าม ==
  • Async ≠ parallel (I/O vs CPU)

3. กับดักข้อสอบ

  • Quick sort “แย่สุด O(n²) — ตอบให้ครบว่าทำไมดีกว่า merge ในบางบริบท (in-place/constant memory)”
  • Hash table “O(1) เสมอ” — ผิด; เสมอคือ “เฉลี่ย”; worst = O(n) เมื่อ collision รุนแรง
  • Linked list เปิดช่อง “insert/delete O(1)” ได้ต้องบอกเงื่อนไข “ถ้ามี pointer อยู่ที่ตำแหน่งนั้น”
  • Pass by reference กับ “object ถูกส่งด้วย reference” — หลายภาษา (Java/Python) จริงๆ ส่ง “reference by value” — ปรับคำตอบตามภาษาที่สอบ
  • Race condition ≠ deadlock — race=ผลผิดเพราะจังหวะ; deadlock=ค้างรอกันวนไป

4. Self-check (ปิดหน้า ตอบก่อน)

Q1: ค้นหาใน hash table และ balanced BST ต่างกันยังไง (เฉลี่ย/แย่สุด)A: hash เฉลี่ย O(1) แต่แย่สุด O(n) เมื่อ collision; balanced BST O(log n) ทั้งเฉลี่ยและแย่สุด + เป็นระเบียบเรียงได้
Q2: Merge sort กับ quick sort ต่างกันด้านไหนบ้างA: merge = O(n log n) ทุกกรณี, stable, ใช้ memory O(n); quick = เฉลี่ย O(n log n) แย่ O(n²), in-place, ไม่ stable
Q3: Overload กับ override ต่างกันA: overload = ชื่อเดียวกันคนละพารามิเตอร์ ตัดสินตอน compile; override = ลูกเขียนทับพฤติกรรมแม่ ตัดสินตอน runtime
Q4: Deadlock เกิดได้เมื่อเงื่อนไขอะไรครบ และแก้ง่ายสุดยังไงA: mutual exclusion + hold and wait + no preemption + circular wait ทั้ง 4 ครบ; แก้ด้วยการทำลายข้อใดข้อหนึ่ง เช่น กำหนดลำดับการ lock (กัน circular wait)
Q5: Async/await เหมาะกับงานแบบไหน ไม่เหมาะกับแบบไหนA: เหมาะงาน I/O-bound (รอ network/disk แบบไม่บล็อก); ไม่เหมาะ (ไม่ช่วย) งาน CPU-bound — ต้องใช้ worker/process คู่ขนานจริง
Q6: ทำไม 0.1+0.2 ไม่เท่ากับ 0.3 และจัดการอย่างไรเมื่อเป็นเงินA: floating point แทนทศนิยมฐาน 2 ได้แค่ประมาณ; ใช้ decimal (หรือ integer หน่วยย่อยสุด) กับงานเงิน และไม่เทียบ float ด้วย ==
Q7: เลือก BFS หรือ DFS เมื่อต้องการ shortest path ในกราฟไม่ถ่วงน้ำหนักA: BFS — เพราะสำรวจตามชั้นระยะทาง ถึงก่อน = สั้นสุดในกราฟที่ทุกเส้นทางราคาเท่ากัน
