05 · AI Fundamental: Skills

อ่าน ~30 นาที · อ้างอิงหลัก: Anthropic — Agent Skills docs (SKILL.md, progressive disclosure); Claude Code skills

1. ต้องเข้าใจ

Skill คืออะไร

  • Skill = แพ็คเกจ “วิธีทำงาน” (procedural knowledge) ที่ agent โหลดมาใช้เมื่อเข้าเงื่อนไข — เก็บไว้เป็นโฟลเดอร์ มี SKILL.md เป็นแกน + ไฟล์ประกอบ
  • เปรียบเทียบให้เห็นภาพ: prompt = สั่งครั้งนี้ · memory = ข้อเท็จจริงสั้นๆที่ต้องรู้ทุกครั้ง · skill = คู่มือขั้นตอนสำหรับ “งานแบบนี้” ที่หยิบมาใช้เมื่อต้อง · RAG = ฐานข้อมูลให้ค้น
  • คุณค่า: agent เรียนรู้วิธีทำงานของคุณครั้งเดียว แล้วใช้ซ้ำได้ทุก session — ไม่ต้องสอนซ้ำใน prompt ทุกครั้ง

โครงสร้างของ skill

  • frontmatter — name (สั้น, ตัวพิมพ์เล็ก + hyphen) และ description (สำคัญที่สุด — ใช้ตัดสินใจโหลด)
  • body ของ SKILL.md — ขั้นตอน/กฎ/ข้อควรระวัง เขียนแบบคำสั่งที่ทำตามได้
  • ไฟล์ประกอบ — references/* (เอกสารอ้างอิงแบบเฉพาะทาง), scripts/* (สคริปต์รันได้), assets/* — โหลดเพิ่มเฉพาะเมื่อต้องใช้
  • Progressive disclosure — ตอนแรก agent เห็นแค่ชื่อ+คำอธิบาย → โหลดเนื้อ SKILL.md เมื่อเกี่ยว → เข้าถึงไฟล์ประกอบเฉพาะเจาะจงเมื่อต้องการจริง — ประหยัด context

เขียน skill ให้ดี

  • Description = trigger: ขึ้นต้นบอก “ใช้เมื่อ…” ให้ตรงกับสถานการณ์จริง (action + งาน) เพราะนี่คือข้อความเดียวที่ agent เห็นตอนตัดสินใจ
  • เขียนเป็น กฎ + เหตุผล (why) ไม่ใช่บันทึกเหตุการณ์/ประวัติ/เลข PR/วันที่
  • หนึ่งบทเรียนหนึ่งกฎ — แยกให้ชัด อ่านแล้วทำตามได้ทันที
  • จัด references เป็นหัวข้อๆ (เช่น references/api.md, references/pitfalls.md) — “ขยายไฟล์เดิมก่อนสร้างไฟล์ใหม่”
  • เนื้อหาใน SKILL.md ต้อง กระชับ — รายละเอียดยาวไปอยู่ references; ตัวหลักคือขั้นตอนที่ต้องทำจริง

วงจรชีวิตของ skill

  • สร้าง เมื่อพบงานที่ทำซ้ำและมีวิธีที่พิสูจน์แล้ว (procedure + pitfall ที่เจอจริง)
  • ใช้ — agent โหลดเมื่อเข้าเงื่อนไข; ถ้าไม่เคยถูกโหลดเลย แปลว่า description ไม่จับ trigger ที่ถูก
  • ปรับปรุง — เจอขั้นตอนผิด/ตกหล่น → patch skill ทันทีที่เจอ (ระหว่างทำงาน); เจอ pitfall ใหม่ → เพิ่มเป็นกฎ
  • รวม/ลบ — skill ซ้ำซ้อนหรือกว้างเกินไป → รวมเข้า umbrella แล้วอ้างอิง; skill ที่ล้าสมัย → ลบ

Skill ต่างจากกลไกอื่นของ agent

กลไกเก็บอะไรโหลดเมื่อไร
Memoryข้อเท็จจริงที่ต้องรู้ทุก session (สถานะแวดล้อม, convention ที่ไม่มีบ้านใน task)ทุกครั้ง (inject เข้า context อัตโนมัติ)
Skillขั้นตอน/วิธีทำงานของ task ชนิดหนึ่งเฉพาะเมื่อ task เข้าเงื่อนไข (โหลดตาม need)
RAGฐานความรู้ขนาดใหญ่ (เอกสาร)ตอนต้องตอบ/อ้างอิง
Tool/Functionsความสามารถลงมือทำ (เรียก API, รันโค้ด)เมื่อ agent ตัดสินใจเรียกใช้งาน
Rules file (AGENTS.md ฯลฯ)convention ระดับโปรเจกต์ทุก session ของโปรเจกต์นั้น

2. ต้องจำ

  • นิยาม: Skills = procedural knowledge, تمโหลด on demand, reusable ข้าม session
  • Progressive disclosure 3 ชั้น: ชื่อ+description → SKILL.md body → ไฟล์ประกอบ
  • องค์ประกอบ skill: SKILL.md (frontmatter: name, description) + references/ + scripts/ + assets/
  • Description ต้องมี trigger ชัดเจน (“ใช้เมื่อ…”) เพราะเป็นข้อความเดียวที่ช่วยตัดสินใจโหลด
  • หลักเขียน: กฎ + why, หนึ่งกฎหนึ่งเรื่อง, ไม่ใส่ประวัติ/วันที่, references แยกหัวข้อ
  • เทียบ: memory=ทุก session, skill=on-demand, RAG=ความรู้, tool=ลงมือทำ

3. กับดักข้อสอบ

  • Skill ≠ memory — ถ้าถามว่า “ข้อเท็จจริงที่ต้องใช้ทุก session” → memory; “ขั้นตอนงานเฉพาะ” → skill
  • Skill ≠ tool — skill บอกวิธีใช้/ลำดับงาน; tool คือความสามารถที่ลงมือทำได้ (บาง skill มีสคริปต์ที่ agent รันผ่าน tool อีกที)
  • “โหลด skill อัตโนมัติทุกครั้ง” — ผิด; โหลดตามเงื่อนไขจาก description (progressive disclosure เพื่อประหยัด context)
  • เขียน skill ยาวเป็นสิบหน้า — ผิดแนวทาง; ย้ายรายละเอียดไป references
  • Skill ที่ดีขึ้นจาก “งานจริงที่ทำซ้ำ” — ไม่ใช่จากจินตนาการล่วงหน้า; เดิมพันของ agents คือแก้ skill เมื่อเจอข้อผิดพลาด

4. Self-check (ปิดหน้า ตอบก่อน)

Q1: Skill คืออะไร นิยามสั้นA: แพ็คเกจวิธีทำงาน (ขั้นตอน+ข้อควรระวัง) ให้ agent โหลดใช้เมื่อเจองานชนิดนั้น — นำกลับมาใช้ซ้ำได้ข้าม session
Q2: Progressive disclosure ของ skill ทำงานยังไงA: ชั้น 1 เห็นแค่ name+description → ถ้าเข้าเงื่อนไขโหลดเนื้อ SKILL.md → เข้าถึงไฟล์ประกอบ (references/scripts/assets) เฉพาะเมื่อต้องใช้ — ประหยัด context
Q3: ทำไม description ของ skill จึงสำคัญที่สุดA: เพราะเป็นข้อมูลเดียวที่ agent เห็นตอนตัดสินใจว่าจะโหลด skill ไหม — ถ้า description ไม่มี trigger ชัดเจน skill จะไม่ถูกใช้
Q4: Memory, skill, RAG ต่างกันยังไงA: memory = ข้อเท็จจริงทุก session; skill = ขั้นตอนโหลดเมื่อเข้าเงื่อนไข; RAG = ฐานความรู้ที่ค้นเมื่อต้องอ้างอิง
Q5: เมื่อเจอว่า skill ที่ใช้อยู่ผิดพลาดกลางงาน ควรทำอะไรA: patch skill แก้ขั้นตอน/เพิ่ม pitfall ทันที (ให้บทเรียนอยู่กับ skill ไม่ใช่ความจำชั่วคราว) แล้วใช้ต่อ
Q6: ยกตัวอย่างเนื้อหาที่ “ควร” ไปอยู่ใน references แทน SKILL.mdA: ตารางอ้างอิงยาวๆ, เอกสาร API, รายการ template/ตัวอย่างเยอะๆ, รายละเอียดเฉพาะ platform — SKILL.md เหลือขั้นตอนและกฎสำคัญ
Q7: เทียบ skill กับ rules file (AGENTS.md/CLAUDE.md)A: rules file = convention ของโปรเจกต์ ติดทุก session ของโปรเจกต์นั้น; skill = วิธีทำงานเฉพาะทาง หยิบเมื่อเข้าเงื่อนไข ไม่ผูกกับโปรเจกต์เดียว
